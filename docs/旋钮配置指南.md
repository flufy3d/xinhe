## 0. 三层配置优先级

实验时一个旋钮的最终取值由三层覆盖决定,**后面的覆盖前面的**:

```
base.yaml  ──── 1. 全局默认(architectural baseline)
   ↓ 覆盖
{entry}.yaml ── 2. 实验入口(pcap_skeleton.yaml / pcap.yaml / recall_probe.yaml...)
   └ state: / training: 块覆盖 base 全局
   └ stage_overrides.{stage_name}: 块再覆盖单 stage
   ↓ 覆盖
curriculum_{entry}.yaml ── 3. 课程文件里的 stages[i].overrides 块
```

例:`mem_out_real_alpha`
- `base.yaml` 没列 → 走 config.py 默认 0.0
- `pcap_skeleton.yaml: stage_overrides.pcap_skeleton.mem_out_real_alpha: 0.0`(iter11 关 MAL)
- `curriculum_pcap_skeleton.yaml: stages[0].overrides.mem_out_real_alpha: 0.1`(iter10 baseline)
- 最终生效值看 `apply_stage_overrides` 调用顺序 —— 一般 curriculum 后调,**curriculum 赢**

**调旋钮前一定先确认你改的是哪一层**:base.yaml 改的是所有实验的默认,curriculum 才是当前 iter 的真实生效值。

## 2. `gate_entropy_lambda`(mix_gate 熵正则)

### 是什么
NeuralMemoryPair 内部把 Hippo 输出 `r_h` 和 Neo 输出 `r_n` 通过一个 **softmax gate** 混合:

```
gate = softmax([<q, r_h>, <q, r_n>])   # (B, T, 2)
mem_out = gate[..., 0:1] * r_h + gate[..., 1:2] * r_n
```

如果训练自由选,模型经常学成 `gate=[1, 0]` 永久无视 Neo(浅 Hippo 先涨起来,Neo 没机会),或者反过来。一旦塌缩,后续 P3 人格注入再用力也白搭。

正则项:

$$
L_\text{gate} = -\lambda \cdot H(\text{gate}),\quad H(p) = -\sum_i p_i \log p_i
$$

加进总 loss → 等价于最大化熵 → 鼓励 gate 双边都有非零权重。

### 数学
- 二元 gate 的最大熵 = `ln(2) ≈ 0.693`
- `H=0.4` 大概对应 `gate ≈ [0.85, 0.15]` 或 `[0.15, 0.85]`,蓝图设的下限
- `H=0.693` = `gate=[0.5, 0.5]` 完全均匀

### 默认 / 典型取值
- **0.0** — 关。当前 baseline。
- **0.01** — 蓝图推荐值,温和。
- **0.05** — 强迫双边参与,可能压住 Hippo 的学习信号。

### 什么时候开
- 监控 `H(gate)` 长期 < 0.4
- 监控 `gate_mean_h` 或 `gate_mean_n` 一直 < 0.1
- write 通路在涨但 Neo 路径明显没被用(看 `aux["gate_mean_n"]`)

**iter4-10 时它默认 0.01 跑了 10+ 轮**,但 mix_gate 没塌缩(因为本来就是 Hippo 主导的 read 任务,Neo 即使权重小也不影响 NIH 召回)。所以 baseline 默认改成 0.0,**只在监控到塌缩时手动开**。

### 副作用
- λ 太大(>0.05)会压制 gate 自然学到的 "Hippo 该多大权重" 的判断,反而伤害 read 通路
- `disable_neo=true` 时无影响(没 Neo 就没 gate,aux 里返回 0)

### 怎么配
```yaml
state:
  gate_entropy_lambda: 0.0      # base.yaml,默认关
```
或在 stage_overrides 里临时开:
```yaml
stage_overrides:
  pcap_skeleton:
    gate_entropy_lambda: 0.01   # 监控到塌缩才开
```

### 监控
trainer 日志里看 `aux["gate_entropy"]`、`aux["gate_mean_h"]`、`aux["gate_mean_n"]`。蓝图阈值:`H(gate) > 0.4` 算健康。

## 3. `mem_out_real_alpha`(MAL 注入开度)

### 是什么
NM 默认是 **MAC 注入**(paper-faithful Titans):W 的输出只写到 fresh_mem prefix 段,real token 通过 attention 自己 query 取。

`mem_out_real_alpha > 0` 启用 **MAL 注入**(iter4 加的):

$$
\text{hidden}[\text{real}, :] \mathrel{+}= \alpha \cdot \text{mem\_out}[\text{real}, :]
$$

意思是 **每个 real token 位置直接加上 NM 在那个位置的输出**,跳过 attention,给 NM 一条直通 lm_head 的捷径。

### 物理意义
- **MAC only**(`alpha=0`):NM 当外挂记忆库,real token 想读必须 attention 去 fresh_mem 段查。**结构干净,但 fresh_mem 容量受限**。
- **MAC+MAL 混合**(`alpha>0`):NM 在每个位置都直接影响 hidden,**read 信号更强**,但 backbone hidden 被推向 vocab space,iter11a 实测 backbone LM 整体崩(NM-on 0% / NM-zero 41%,ΔNM −41pp)。

### 数学
注入位置(`xinhe_model.py:288-290`):
```python
real_alpha = float(getattr(self.config, "mem_out_real_alpha", 0.0))
if real_alpha > 0:
    delta[:, real_start:real_end, :] = real_alpha * real_proj
```

注意 `mem_alpha_override` 是另一个独立旋钮(`learning_session` 阶段 1 / NM-zero ablation 用,把整个 mem 通路屏蔽),不要混淆。

### 默认 / 典型取值
- **0.0** — 纯 MAC,paper-faithful。当前 iter11 配置。
- **0.1** — iter4 在 `recall_probe` 微数据集上让 read 从 10% 跳到 100%。
- **0.2** — iter10 在 skeleton 上尝试,write 涨到 97% 但 read 依然 0%。
- **>0.3** — 实测 backbone hidden 被推爆,LM 整体崩。

### 什么时候开
**目前结论是先关**:iter11 A 实验配 `nm_aux_weight=0.5` 时,如果再叠 MAL,会推 backbone hidden 到 vocab space → backbone LM 崩。

未来组合策略:
- 跑 Q-K Projection 时:**先保持 0.0**(让 Q-K 单独发挥),iter 后看 read 起没起来再决定
- 候选 E 实验(`docs/v9.5_skeleton_iter4-11_全记录` 推荐):**read turn 上 alpha>0,其他 turn alpha=0**(per-turn override,代码暂无入口)

### 与其他旋钮的交互
- 跟 `nm_aux_weight` **不要同时开大**(iter11a 教训):aux loss 让 W 输出趋近 value embedding,MAL 再把 value embedding 灌进 hidden → backbone 接管不了 LM
- 跟 `mem_alpha_override=0.0`(eval 用 NM-zero ablation)正交,后者会同时屏蔽 MAC + MAL

### 怎么配
```yaml
stage_overrides:
  pcap_skeleton:
    mem_out_real_alpha: 0.0     # 纯 MAC,iter11 当前
    # mem_out_real_alpha: 0.1   # 给 read 信号(单开 OK,跟 nm_aux 同开会崩)
```

## 4. `nm_aux_weight`(NM-only aux loss)

### 是什么
iter11 A 实验加的旋钮。**绕过 backbone**,让 Hippo W 的输出 `mem_out` 直接过 frozen `lm_head` 算 cross-entropy 预测 value token:

$$
L_\text{nm\_aux} = w_\text{aux} \cdot \text{CE}\big(\text{lm\_head}(\text{mem\_out}_\text{real}),\ \text{value\_label}\big)
$$

只在 **value-span position**(`weights > 0.5`)上算,排除 distract 段 —— 否则 W 会学成 distract 复读机。

### 物理意义
- 蓝图原设:W 学 "key → value" key-value mapping,read 时 backbone 通过 attention 从 fresh_mem 提
- 实战发现 read 通路死锁(iter4-10 全 0%)
- A 实验绕过 backbone,**直接逼 W 输出 = value embedding**,验证 "W 能不能学到 value readout" 这个能力
- iter11a 结果:**W 确实能学**(NM-only LM head 在 value-span 上 acc 起来了)→ 证明 read=0% 不是 W 表征问题,是 fresh_mem 通路结构问题

### 数学
代码在 `xinhe_model.py:259-277`,核心步骤:
1. 取 `mem_proj[:, real_start:real_end, :]` —— NM 在 real token 位置的输出
2. shift 一位对齐 next-token prediction
3. mask 出 `weights > 0.5` 的 value-span 位置(distract 段 lm_only=0.04 被排除)
4. 走 `linear_cross_entropy`(cut-CE)避免材化 (B,T,V) logits
5. `aux_loss_terms.append(nm_aux_weight * nm_ce)`

### 默认 / 典型取值
- **0.0** — 关。base 默认。
- **0.5** — iter11 实验值,跟主 LM loss 等权。
- **>1.0** — 没试过,会过分推 W 学复读 value token,可能破坏 W 当 key→value mapping 的语义

### 什么时候开
- 怀疑 W 学不到 value readout(read=0% 持续)
- 想绕过 backbone 验证 "W 能力" vs "通路结构" —— A 实验本质就是诊断工具
- **当前(post-iter11):0.5 已确认 W 有能力,问题在通路。Q-K iter 阶段建议关回 0.0**,因为 Q-K 直接修通路,不需要 aux loss 也能让 read 起来。如果 Q-K 失败再重新打开做 B 实验。

### 与其他旋钮的交互
- 跟 `mem_out_real_alpha` 互斥(见上节)
- 跟 `value_weight_cap` 关联:aux loss 在 value-span 上算,cap 决定 value-span 的损失放大倍数(`value_weight_cap=5.0` 时 value token 的 LM 损失 ×5,跟 aux 配合得更紧)
- 跟 `lm_only` 的 0.04 系数关联:distract turn 用 lm_weight=0.04 等于 value-span 权重 ~25× distract,aux 在 value-span 上才生效

### 怎么配
```yaml
stage_overrides:
  pcap_skeleton:
    nm_aux_weight: 0.0          # 默认关,正常训练
    # nm_aux_weight: 0.5        # 开 A 实验
```

## 4b. `enable_qk_projection`(TNT Q-K Projection)

### 是什么
TNT 论文(ICLR 2026)针对 Titans 类 deep-memory 模块的 **Challenge 2** —— compression / retrieval 域不匹配 —— 提出的解法。

Hippo 写入时 W 学的是 `f(W, k_t) ≈ v_t`(key→value 映射),但 retrieve 时喂的是 `q_t`。冻 backbone 下 `q` 和 `k` 来自不同 Linear 投影且无端到端协同训练,**`q` 落在 W 学过的 key 子空间之外** → MLP 检索退化(就是 iter4-12 read=0% 的根因假设)。

Q-K Projection:维护 `M_t = Σ_{τ≤t} k_τ k_τ^T`(d×d 累加矩阵,跨 turn carry),retrieve 时:

$$
o_t = f(W_t,\ M_t \cdot q_t)
$$

`M·q` 把 q 强制压回 `span{k_1,...,k_t}` 子空间,即使 q 与 k 的 token-level 分布天差地别。

### 数学
- 累加规则:`M_t = M_{t-1} + k_t k_t^T`(线性,半正定,单调增长)
- 写入路径(`store_memories`):每 chunk 计算 `Σ_n k_n k_n^T` 加到 past_M
- 读取路径(`retrieve_memories`):`q' = M @ q`,再喂 W

paper 用单位 L2 norm key,所以分母 `||k||²` 全 1,直接累加 outer product。NeuralMemoryPair 默认 `qk_rmsnorm=True`,k 经 RMSNorm 后近似单位 norm,故省略归一项。

### read_before_write 语义对称
跟 W 一样,M 也采用"读用入口值,本 turn keys 不参与本 turn 读":
- read_before_write=True 路径:retrieve 用 `state.qk_M`(进入函数时的 M,不含本次输入的 keys)
- store loop 累加新 keys 到 M,作为下一次 read 的 M

这避免"自窥"(token 读到刚由自己写入的 M 痕迹),与 W 的 `read_before_write` 保持对称。

### 实战影响 ─ 重要 ─
**第一 turn 时 M=None,projection 无效**。当 read turn 是 episode 第一个 turn 时,Q-K 不起作用 —— 但 skeleton 任务的 read turn 永远是最后一个,前面 15 turn 已累积了大量 keys。所以这条限制实战不影响。

### 默认 / 典型取值
- **False** — 默认关。
- **True** — 开启。无连续标量参数,纯开关。

### 什么时候开
- 现在(post-iter12)Q-K iter 第一次开。看 read first-token NM-on 能否从 0% 起来。
- 如果 read 起来:**iter4-12 read=0% 的根因确认是 q/k 域不匹配**,Q-K 是修复。
- 如果 read 仍 0%:Q-K 不是关键,问题在更深处(如 fresh_mem 通路结构、或 chunk 内 inner-SGD 收敛性)。

### 与其他旋钮的交互
- 跟 `mem_out_real_alpha`(MAL):正交,可同开。MAL 用 mem_out(包含 retrieve 结果)灌 hidden;Q-K 改 retrieve 算法本身。**iter11 教训:MAL 与 NM aux 同开伤 backbone LM**。Q-K iter 建议先保 MAL=0。
- 跟 `nm_aux_weight`:基本正交。aux 让 W 学 value readout;Q-K 让 q 能 reach W 的 key 域。两者攻击 read 通路的不同环节,可同开。
- 跟 `hippo_retention`/`hippo_base_lr`:无直接交互。M 是独立累加状态,不进 inner SGD 内层。
- 跟 `disable_neo`:正交。disable_neo=True 时仍能开 Q-K,因为 Q-K 在 Hippo 内部。

### 怎么配
```yaml
stage_overrides:
  pcap_skeleton:
    enable_qk_projection: true       # Q-K iter 入口
    mem_out_real_alpha: 0.0          # MAL 仍关(iter11 教训)
    nm_aux_weight: 0.5               # NM aux 保持(iter11b)
```

### 监控
- `state.hippo.qk_M.norm()` 跨 turn 单调增长是健康
- 突然爆炸(>1e6)→ keys 没归一化,检查 `qk_rmsnorm` 是否被关
- read NM-on / NM-zero / Δ 三口径 strict eval 是终极判据

### 实现位置
- 配置字段:`xinhe/model/config.py: XinheConfig.enable_qk_projection`
- 透传链:`xinhe_model.py:108 → neural_memory_pair.py:NeuralMemoryPair.__init__ → _build_neural_memory → NeuralMemory.__init__`
- 状态:`NeuralMemState.qk_M` 第 6 字段
- 累加:`neural_memory.py: store_memories` line ~700(`keys = self.k_norm(keys)` 之后)
- 投影:`neural_memory.py: retrieve_memories` line ~1040(`queries = self.q_norm(queries)` 之后)
- 测试:`tests/test_neural_memory_pair.py` 6 个 `test_qk_projection_*`

## 5. 周边相关旋钮(简表)

| 旋钮 | 类别 | 默认 | iter10 调过 | 说明 |
|---|---|---:|:---:|---|
| `hippo_retention` | TTT inner | 0.99 | **0.999** | α_t init = `1 - σ(_logit(1-r))`,outer Adam 可学。0.999 = 单步衰 0.1%,16 turn 累积保留 98%。**不是单纯的 mem 衰减,是初始 bias** |
| `hippo_base_lr` | TTT inner | 1e-2 | **5e-3** | inner SGD 每步 cap,`θ_t = σ(Linear(x))·base_lr`。减半让 distract 不那么粗暴擦写 W |
| `mem_chunk_size` | TTT inner | 128 | 128 | turn 内 inner SGD 步数 = turn_max_tokens / chunk。**不要改成 256**(iter10 NaN 教训:bf16 + vmap(grad) 在 256 样本数值不稳) |
| `disable_neo` | 架构 | false | per stage | 关 Neo MLP 走 paper-faithful 单 Hippo 路径。`true` 时 `gate_entropy_lambda` 无效(没 gate)。当前 iter11 `false`(保留 Neo+Hippo) |
| `lm_only` weight | 数据 | 0.04 | **0.04** | `_resolve_lm_weight("lm_only")` 返回,distract turn 的 LM 系数,iter10 从 0.1 降到 0.04 把 value-span 信号比放大 25× |
| `value_weight_cap` | 数据 | 1.0 | **5.0**(iter10)| value-span token 在 LM loss 里的权重上限,5.0 让 value token 损失 ×5(给 outer Adam 更强 value 梯度) |
| `freeze_gate_q` | 基线对照 | false | — | 冻 NeuralMemoryPair.gate_q.weight 给基线对照用,正常实验不开 |
| `mem_alpha_override` | eval / phase | None | — | 不是 yaml 配的,是 forward 时显式传。NM-zero ablation 传 0.0 屏蔽整个 mem 通路 |
| `n_persistent_per_layer` | 架构容量 | 16 | **4**(skeleton)| per-layer K/V tokens 数量,小数据 / fast iter 降到 4 减少容量 |
| `n_mem_tokens` | 架构容量 | 16 | 16 | fresh_mem prefix 长度,paper Titans MAC 一般 8-16 |
| `compile_backbone_layers` | 性能 | false | true(iter10)| torch.compile 每个 Qwen layer body,NM 在 compile 外 |
| `per_segment_checkpoint` | 显存 | false | false | gradient checkpointing 每段。v9 必须保 false(vmap + checkpoint saved_hooks 冲突) |
| `plugin_lr_multiplier` | 优化器 | 1.0 | 1.0 | NeuralMemoryPair 参数组 lr 倍率。0 = 冻结整个 memory(基线对照) |

## 7. 怎么改 / 怎么验

### 改一个旋钮
1. 确定改哪一层(base.yaml 永久 / entry yaml 本实验 / curriculum stage 课程级)
2. 用 grep 检查这个 key 有没有被多层重复设(curriculum 优先级最高)
3. 改完跑 `pytest tests/test_neural_memory_pair.py tests/test_model.py` 确认不破
4. 跑 50-100 步 smoke 训练,看 ema_loss 不 NaN

### 加一个新旋钮
1. `xinhe/model/config.py` 加字段 + 默认值 + `from_yaml` 里 stage_overrides map
2. `scripts/train.py` `apply_stage_overrides` 里加 key 映射
3. 用它的地方加 `getattr(config, "new_knob", default)`(向后兼容)
4. 写测试覆盖 on/off 两种 case
5. 来这个文档加一段

### 验配置生效
```python
from xinhe.model.config import XinheConfig
cfg, _ = XinheConfig.from_yaml('configs/pcap_skeleton.yaml')
print(cfg.gate_entropy_lambda)   # 看 base 默认是不是真的进来
# 再叠 stage override 测试见 scripts/train.py apply_stage_overrides
```

### 监控旋钮效果
- `aux["gate_entropy"]` / `aux["gate_mean_h/n"]` —— gate 塌缩否
- `mem_norm` 训练日志 —— W 注入有没有 collapse
- `validate_memory.py` strict eval `--max-episodes 200` 看 first-token NM-on / NM-zero / ΔNM 三口径
